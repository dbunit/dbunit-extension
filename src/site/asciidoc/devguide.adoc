= Developers Guide

[#overview]
== Overview

Contributions to dbUnit are welcome. This page is the map for the rest of the
"Developing DbUnit" section — a fast-path checklist if you're new, and a set of links to
the focused page for whatever you need next.

[#quick-start]
== Contributor Quick Start

. Fork the repository and branch from `main` — see
  link:github/pullrequests.html[Branching & Pull Requests].
. Write the code and the tests that cover it — see
  link:codingstandards/testconventions.html[Test Conventions].
. Format it — see link:codingstandards.html[Coding Standards].
. Commit, following the Conventional Commits format, bundling the `changes.xml` entry
  in the same commit — see link:commits.html[Commit Requirements] and
  link:changelog.html[Changelog].
. Push and open a pull request — see link:github/pullrequests.html[Branching & Pull
  Requests].

[#where-to-go-next]
== Where to Go Next

link:codingstandards.html[Coding Standards]:: General Java style, JavaDoc conventions,
and dbUnit's own test-writing conventions, plus the tooling (Eclipse formatter,
Checkstyle, Modernizer) that partially automates and enforces them.

link:commits.html[Commit Requirements]:: Atomic commits, the same-commit bundling
rules, the `fixup!`/autosquash workflow, and the full Conventional Commits format.

link:changelog.html[Changelog]:: The `changes.xml` schema, placement rules, and the
Dependabot automation that handles routine dependency bumps for you.

link:github.html[GitHub Workflow]:: Filing issues, the branch/PR process, and the CI
workflows that watch your branch.

link:building.html[Building]:: Generating the jar and the site, and the quality gates
(Checkstyle, Modernizer, JaCoCo, japicmp) that run along the way.

link:integrationtests.html[Integration Tests]:: Running the test suite against a
specific database, in an IDE, or against every supported database at once.

link:releasing.html[Releasing]:: The maintainer-facing release procedure.
