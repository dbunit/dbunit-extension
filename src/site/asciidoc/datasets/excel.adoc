= Excel (XLS)

link:../apidocs/org/dbunit/dataset/excel/XlsDataSet.html[XlsDataSet]
reads and writes MS Excel dataset documents. Each sheet represents a table.
The first row of a sheet defines the column names, and the remaining rows
contain the data.

[source,java]
----
IDataSet dataSet = new XlsDataSet(new File("dataset.xls"));
----

A blank or absent cell is read as a null value; a text cell that holds an empty
string is read as the empty string. Because every column is
declared in the header row, a later row with a blank cell keeps the column —
Excel has no "extra columns" problem. For how a cell value becomes a typed
column value — binary/BLOB syntax, literal and relative dates, UUID literals,
and booleans/numbers from strings (in text cells) — see
link:values.html[Dataset Values].

An Excel cell holds a number as a `double`, and dbUnit writes a date or a timestamp as a
number of milliseconds, so an Excel dataset keeps 15 to 17 significant digits of a number and a
timestamp to the millisecond. A `NUMERIC` or `DECIMAL` value of more than 15 digits, a `BIGINT`
above 9,007,199,254,740,992 (2 to the power of 53) and the digits of the fraction of a second of a
timestamp past the third change when dbUnit writes them to an Excel file and reads them back,
so such a dataset does not verify against the table it was written from, and a `BIGINT` at the
limit of its range, such as `Long.MAX_VALUE`, comes back with the wrong sign. The other formats
keep every digit: use link:json.html[JSON] or link:yaml.html[YAML], for example, for a dataset
that holds such values.

== Dependency

dbUnit depends on https://poi.apache.org/[Apache POI] to read/write Excel
files, but marks it `optional` so projects that don't use `XlsDataSet` don't
pull it in. Add it yourself to use this format:

[source,xml]
----
<dependency>
  <groupId>org.apache.poi</groupId>
  <artifactId>poi</artifactId>
  <version>5.2.5</version>
</dependency>
----
