= ValueComparer Comparison
Jeff Jensen

== Overview

Introduced in link:../changes.html#a2.6.0[Release 2.6.0], the
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparer.html[ValueComparer]
is a strategy interface enabling any type of comparison, not only equality.

It enables comparing difficult-to-compare column values such as:

* auto-incrementing ids
* timestamps

It enables comparisons such as:

* greater-than
* less-than
* contains
* regular expression match
* complex multi-column-based
* dynamically choosing the ValueComparer based on criteria

== Usage

This flexibility and power has slightly more complex usage than equality comparison.

To use
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparer.html[ValueComparer]
comparison,
the dbUnit dataset files do not change.
Instead, the tests use dbUnit assert methods that work with
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparer.html[ValueComparer]s.

=== Core ValueComparer Classes

Package
link:../apidocs/org/dbunit/assertion/comparer/value/package-summary.html[org.dbunit.assertion.comparer.value]
contains the
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparer.html[ValueComparer]
implementations and related interfaces/classes.

The
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparers.html[ValueComparers]
class has singleton instances of the ones provided by dbUnit
plus pre-configured variances (e.g.
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparers.html#isActualWithinOneMinuteNewerOfExpectedTimestamp[isActualWithinOneMinuteNewerOfExpectedTimestamp]).
Start with these as they provide for most comparison needs.

For a column whose exact content a test does not control but whose format it
does - a database-generated id, a UUID, a formatted identifier, a timestamp
rendered into a text column -
link:../apidocs/org/dbunit/assertion/comparer/value/RegularExpressionValueComparer.html[RegularExpressionValueComparer]
(also
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparers.html#regularExpressionValueComparer[ValueComparers.regularExpressionValueComparer])
takes the expected dataset value as a regular expression and passes when it
matches the actual value in its entirety, the same rule as
`java.lang.String.matches`. The pattern is matched against the actual value's text as dbUnit
gives it. For a column of another type than text that is the text of the Java value, not the
text the database shows: a timestamp ends in its fraction (`2026-01-02 10:00:00.0`), a decimal
keeps the scale of its column (`12.50` in a `DECIMAL(10,2)` column), and a binary value is its
Base64 text. A pattern that ignores this does not match, and the comparer's part of the failure
message, `Actual value='...'`, shows the text that was matched. To match only part of the value, wrap the pattern in
`.*` on both ends, e.g. `.*[0-9]{4}.*`; a `.` does not cross a line terminator,
so prefix the pattern with `(?s)` when the actual value may contain a newline. When
`DefaultPrepAndExpectedTestCase` or `@DbUnitExpected` verifies a table, the rows are lined up
before they are compared, and the columns that have a comparer of their own, such as this one
on a generated id, are the last columns they are sorted by, in their original order. Rows that
tie on every other column and hold different patterns in a numeric column fail with a message
that says so - see
link:../components/verifytabledefinition.html#sortmode[Sort Mode].
`Assertion.assertWithValueComparer` and the other assert methods compare the rows in the order
the two tables give them, so when that order is not fixed, sort both tables, for example with
link:../apidocs/org/dbunit/dataset/SortedTable.html[SortedTable].

Some implementations are deliberately left off
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparers.html[ValueComparers]
because it eagerly instantiates every instance it declares, and doing so there would force
an optional dependency onto every user of that class instead of only those who need it;
construct these directly instead. For example,
link:../apidocs/org/dbunit/assertion/comparer/value/IsActualEqualToExpectedJsonValueComparer.html[IsActualEqualToExpectedJsonValueComparer]
compares JSON/JSONB column values (e.g. MySQL `JSON`, PostgreSQL `json`/`jsonb`, H2 `JSON`)
by their parsed document structure instead of raw text - ignoring object member order and
insignificant whitespace, both of which a database may rewrite when it stores a JSON value -
and needs the optional `jackson-databind` dependency also used by
link:../apidocs/org/dbunit/dataset/json/JsonDataSet.html[JsonDataSet]. Without it on the
classpath, creating the comparer fails with a `DatabaseUnitRuntimeException` that names the
dependency to add. The comparer parses a JSON value whatever the length of its strings, as
`JsonDataSet` reads one: it lifts the limit of 20,000,000 characters that Jackson 2.15 and later
set on a string.

Two values are equal when their documents are the same, as JSON defines it:

* Whitespace between the tokens and the order of an object's members do not matter, while the
order of an array's elements does.
* A member with the value `null` differs from a missing member.
* A number is compared exactly, with every digit it has: `1.5` and `1.50` are the same number,
two fractions that differ only past what a `double` holds differ, and a whole number differs
from a number with a fraction, so `1` and `1.0` are not equal.
* A value must be one JSON document. Content after the first value, such as `{"a":1} xyz` or a
second document, fails the comparison with a `DatabaseUnitException` that names the column and
the row, as any other invalid value does. Jackson 2.9 and later can check for it; an older
Jackson ignores the content.

It is easy to add your own implementations of the
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparer.html[ValueComparer]
interface,
either directly or using base classes such as
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparerBase.html[ValueComparerBase]
and
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparerTemplateBase.html[ValueComparerTemplateBase].

Please let us know of comparison needs not handled by the
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparer.html[ValueComparer]
implementations and
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparers.html[ValueComparers]
instances as maybe we should add it to dbUnit.

link:../testcases/PrepAndExpectedTestCase.html[PrepAndExpectedTestCase overview]

== Example

This example shows defining the value comparers
for comparing the expected table to the actual table.
In addition to the expected and actual table parameters,
Assertion.assertWithValueComparer()
uses a default value comparer
(used for columns not listed in the columns map)
and the column value comparers map for comparing specified columns.

It uses the value comparer instances defined on the
link:../apidocs/org/dbunit/assertion/comparer/value/ValueComparers.html[ValueComparers]
class.

[source,java]
----
@Test
public void testExample() throws Exception
{
    ITable expectedTable = ...; // declare the expected table
    ITable actualTable = ...;  // declare the actual table
    ValueComparer defaultValueComparer = ValueComparers.isActualEqualToExpected;
    Map<String, ValueComparer> columnValueComparers =
            new ColumnValueComparerMapBuilder()
                    .add("COLUMN1", ValueComparers.isActualGreaterThanExpected)
                    .add("COLUMN2", ValueComparers.isActualLessOrEqualToThanExpected)
                    .build();

    Assertion.assertWithValueComparer(expectedTable, actualTable, defaultValueComparer, columnValueComparers);
}
----
